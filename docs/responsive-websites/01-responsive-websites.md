# Responsive websites

## What is responsive web design?

**Responsive web design** is an approach in which a website changes its layout automatically to fit the screen of the device it's opened on. You first met the term in [Chapter 1](../foundations/06-platforms). On a wide monitor, a responsive page might show content in four columns side by side. On a phone, the same content is stacked in a single column you scroll through.

Responsive design is more than shrinking everything. A smaller screen means less space, so elements may **change form** as well as size:

- **Navigation** - a row of links across the top of a desktop page often turns into a menu icon on a phone.
- **Columns** - several columns of content become fewer columns, or one.
- **Images** - large pictures are scaled down, cropped to a different shape, or shown one at a time.
- **Text** - headings may get smaller, and long descriptions may be shortened or moved further down.

The goal is that people can do the same things in a similar way, whatever device they happen to be holding. If a resident can check a machine's status on a laptop at home, they should be able to do the same on a phone in the stairwell.

## Why responsive design matters

People switch between devices all day: a laptop at work, a phone on the bus, a tablet on the sofa. A website that only works well on one of them excludes everyone else. Responsive design brings several benefits:

- **Better usability** - content fits the screen, so nothing is cut off, too small to read, or hidden off the edge.
- **Reach on every device** - mobile visitors get a good experience instead of leaving for a competitor.
- **Lower cost** - you design and maintain one flexible website instead of a separate site for each device.
- **Better accessibility** - layouts that reflow also handle zoom and large text, which many people with low vision depend on.

Responsive websites are also a very common task in UX jobs. Many companies need websites or web-based tools more often than native apps, so a responsive project in your portfolio shows employers that you can handle this kind of work.

## Dedicated mobile apps vs. responsive web apps

When you design for phones, you have two options. A **dedicated mobile app** (also called a **native app**) is installed from an app store and opened from an icon on the home screen. A **responsive web app** is a website that adapts to the device and opens in the phone's web browser. Both can show the same information, but they feel different to use and have different costs.

### Dedicated mobile apps

| Advantages | Disadvantages |
| --- | --- |
| Work offline once installed, at least partly | Cost more to build and maintain |
| Use built-in device features, such as the camera, microphone, location, and notifications | Usually need separate versions for Android and iOS |
| Allow richer interactions, such as complex gestures and animations | Must pass app store review before each release |
| Can be personalized based on the user's settings and habits | Take up storage, which is a real problem on cheaper phones |

### Responsive web apps

| Advantages | Disadvantages |
| --- | --- |
| Faster and cheaper to build | Need an internet connection or mobile signal |
| Nothing to download, so no storage is used | Harder to discover, because they aren't listed in app stores |
| Work on any device with a browser | Must be tested and maintained across many screen sizes |
| One link opens the same content everywhere | Have more limited access to device features |

Neither option is always better. Many products offer both, and the choice depends on what users need, where they are, and what the business can afford. For people with limited data plans or unreliable connections, the offline ability of an app can matter a lot. For people with little storage or old devices, a website may be the only option that works.

*WashSlot example:* the WashSlot app stays, because its reminders and offline status cache work well in the basement, where the mobile signal is weak. The website covers the residents the app can't reach: Grace, who doesn't want to install anything; Kofi, whose phone has no storage left; Tomasz, who wants to book from his laptop; and the shared tablet in the laundry room, which uses the building's Wi-Fi.

## What you'll design in this chapter

The process for a website is the one you already know: empathize, define, ideate, prototype, and test. You can reuse most of your earlier research, such as personas, user stories, journey maps, and competitive audits, because the users and their problems haven't changed. What's new is the medium. You'll plan how the website is structured, how its pages are laid out, and how each layout changes from desktop to tablet to phone.

*WashSlot example:* the designer revisits the competitive audit from Chapter 2 and looks at the websites of the same competitors this time. Two of them have a website that only works well on desktop: on a phone, the booking calendar runs off the right edge of the screen. The designer notes this as a clear opportunity.

::: tip Key takeaway
A responsive website adapts its layout to any screen, so people can do the same tasks on any device. Dedicated apps work offline and use device features but cost more and take up storage; responsive web apps are cheaper and need no download but require a connection. Many products offer both, and you choose based on your users' needs.
:::
